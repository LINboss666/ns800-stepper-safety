## 3. 实现范围：一个 R7F8 派生执行器，四项窄适配

从绑定旧执行器创建 `tools/m8r3_serial_chain_r7f8.py`，只在新目录维护。不要覆盖旧执行器，不引入通用脚本语言、任意表达式或任意命令模板系统。

### E1 — 异步作业的有界状态轮询

增加专用于 `diag_profile learn_status` 的轮询合同，与原有“等待 ACCEL／DECEL 到巡航”的 poll 分开。

- 只发送预先声明的只读查询；上限同时包含次数、时间窗和间隔，且受会话、arm 通电、start 运动预算中最早截止约束。
- RUNNING／CANCEL_PENDING 可在字段一致时等待；不靠“响应中没有 FAILED”判成功。
- 绑定本次真实受理 JOB_ID，核对 want／窗口／方向／归属／凭据及计数一致性，禁止把旧 DONE／旧 FAILED 当本轮结果。
- DONE 正例要求 owner=FREE、zero／learn 凭据有效、ADC／SG 独立样本达到请求数、候选结果可用；不能只认 st=DONE。
- CANCELLED 正例对应同一作业的取消受理；若取消时已 DONE，记未捕获活动取消，不能改写为取消成功，也不能自动再开一枚。
- 其他终态按阶段明确判据立即结束；协议矛盾、错误 JOB_ID、缺字段、裸 NUL、非法 UTF-8、缺提示符、危险文本立即 STOP，不允许等待后续好响应把首错冲掉。
- 每次 poll 原字节、RX hash、命令、序号、状态与结束原因分别落证。纯查询轮询不消耗 learn 请求次数，也不作为重新创建作业的 retry。

实现最小接口与具名错误由你选择，但必须给出可审的 schema／例子及固定接受面。

### E2 — 从 STARTED 绑定 JOB_ID 并安全生成取消命令

- 仅在本次 learn 请求的完整响应中，从唯一、整行匹配且参数一致的 STARTED 行绑定 ID；先通过原字节门与步骤判据，再发布绑定。
- ID 是允许范围内的整数。缺失、多个匹配、0／越界、带命令字符或字符串尾缀一律拒绝。
- 使用“命名 learn 步骤 → JOB_ID”的有限绑定。后续只能把这个数字放进固定 `diag_profile learn_cancel <ID>` 参数位，以及同作业状态断言。
- 不使用 eval／exec、任意 format 模板、shell 展开；不从任意日志、旧会话、IDLE 状态或上轮事故里捞 ID，也不默认 1。
- 取消试验与最终 DONE 试验各有自己的绑定。作用域、重复绑定规则明确；不得跨阶段、跨会话或跨作业串用。
- 批准绑定的是固定计划与解析／生成规则；运行时记录派生命令、ID 来源 RX hash、来源步骤和规则身份，不回写获批 plan 或假装实际 ID 已在批准前确定。
- 配置缺失／未知引用／绑定失败必须在对应写动作之前阻止发送。

### E3 — 取消的显式额度

- 在派生执行器中把 `diag_profile learn_cancel` 单列为修改状态的动作，建议键 `diag_profile_learn_cancel`；中央映射、计划验证、批准账、步骤预约／核销、汇总全部一致。
- 取消额度缺失、为 0、错键、n 不为 1、已耗尽，必须在发送前拒绝。
- `learn_status` 不被误算作 learn／cancel；learn 请求与 cancel 分别计数。取消命令不能放进只读 poll 自动重发。
- “cancel 返回已终态／NOT-CANCELLED”也算一次发送尝试，不能退还额度再试。
- 缺省新额度按 0 处理，不把旧计划或旧令牌自动升级为含取消授权。
- 其他本包没有改的命令面沿用原合同；新增任何修改动作都须显式计数，不再依据“映射里没有就当只读”推论。
- 若要给 arm 新增独立次数键，应在本轮 schema／账本一并实现并默认 0；不能通过放宽旧映射绕过。具体字段名可自行确定，语义与计划计数必须可复算。

### E4 — arm 通电截止与固定清理对账

- 保留 motor_start 发送尝试开始的运动截止；另外在 motor_arm 写入尝试之前建立已声明的通电时限。即使短写、写异常、无回包，也承担已建立的撤能义务。
- arm 后尚未 start、学习／查询／等待、正常 stop 后仍 armed 的区间，均不能脱离通电时限。不能等到 start 才开始约束，也不能靠正目标值推定已经起转。
- 业务步骤的读／睡眠／轮询不得超过当前最早截止；进入清理时使用独立、预留的清理窗口。计划缺少或矛盾的 arm 时限在真实写前具名拒绝。
- 人工硬件禁能仍是主机失效时的独立手段；主机软件截止不能升级成物理实时停机保证。
- **本轮保留固定清理三条 motor_stop→motor_disarm→motor_status**，不开发可任意编辑的清理脚本。即使正常段已 stop/disarm，最终固定清理的重复发送仍分别记账；合成计划必须把两组都列出来。
- 延续“清理预约失败仍尽力撤能”的现有义务，但这种超额／记账失败必须报告，本场不得 status=OK。不要为满足额度 0 而禁止必要撤能。
- 一条清理响应丢失，不能取消后续 disarm／状态取证机会；原始首错、清理错误、额度超额分别报告，可信禁能只能由新的完整快照承担。
- 正常命令顺序保持零目标确认→dir→arm→确认→target→start。learn_cancel 不代替 stop/disarm，作业异常不能吞掉运行截止。
