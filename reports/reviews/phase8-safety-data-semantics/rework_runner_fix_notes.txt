2. SD-NEW-01 (ONLY 零执行却 PASS)
   缺陷: 旧 want_variant() 只判断"是否匹配", 不校验 ONLY 是否属于已知集合;
         ONLY=ZZZ_NO_VARIANT 时两变体都被跳过, overall 仍 0, 汇总反而说"两个变体全部真执行"。
   修法: (a) validate_only() 在 require_outside_repo/mkdir/rm/重定向/编译**之前**执行;
         (b) 只接受完整名称 off_target/on_target; 未知词、合法词夹带未知词、空值或纯空白、
             重复词一律 rc=4 并打印原因, 不创建也不清理任何目录;
         (c) ONLY 与 REVERSE=1 的组合显式拒绝(不静默忽略参数), 因反向固定覆盖 off_target 全台账;
         (d) 记录 SELECTED 与 EXECUTED 两个集合, 汇总分别打印"选择集合/实际执行集合/NOT_RUN";
             只有默认选择且两变体都真执行且通过, 才声明"两个变体全部真执行";
             显式单变体只声明该变体, 未选择侧写 NOT_RUN(未被 ONLY 选择)。

3. SD-NEW-02 (异常终止被算成反向成功)
   缺陷: 旧 reverse_case() 只排除 rc=0, 未要求合同的正常业务失败 rc=1, 也未核对完整台账与
         SUMMARY; 复审用 -Wl,--wrap=main 注入 SIGTERM(Linux 得 143)后仍记 META-OK、外层 rc=0。
   修法: META-OK 必须同时满足 ①副本构建成功 ②子进程 rc==1(夹具唯一承认的正常失败退出码)
         ③validate_ledger() 通过: 每个必需 id 恰好出现一次、无未登记用例、SUMMARY 恰好一条、
           cases/pass/fail 与实际 CASE 行数一致且 pass+fail==cases ④指定业务失败身份全部判 FAIL。
         非 0 非 1 的退出 => INFRA-FAIL, 外层 rc=4; rc==0 或缺期望身份 => NOT-DETECTED, 外层 rc=1。
         按复审要求**不特判 143、不只看 rc>=128**(本机 raise(SIGTERM) 实测返回 3, 同样被拒)。
   判据不放宽: 复审 §6.2.4 指出 R1 还会使 SD05c 合理失败, 这是当前已知结果, 不算基础设施故障;
         runner 把它登记成"额外失败(登记但不改变判定)"并在 META-OK 行内记录 实际FAIL行/额外失败 计数。
   共用实现: validate_ledger() 同时用于正常变体与反向, 未另写一份"正确解释器";
         台账复核入口 SD_VALIDATE_FILE=/SD_VALIDATE_VARIANT= 只读既有产物, 不编译不运行不动目录,
         回归用它验证两类不完整输出确实被真实校验器拒绝。

4. 场景回归真实结果(sd_runner_rework_check.sh, 外层 rc=0)
   通过=21 不符=0 环境故障=0
   - 拒绝场景: unknown/mixed/blank/dup ONLY 与 REVERSE+ONLY 共 5 项 => 全部 rc=4,
     且每次都核对"目标 OUT_DIR 未被创建 + 沙盒 KEEP 标记完好"(拒绝发生在破坏之前)
   - 合法单变体 ONLY=off_target => rc=0, 只声明 off_target, on_target 标 NOT_RUN
   - 异常注入(exit3 与 sigterm 两种) => R1/R2 均 "INFRA-FAIL 非合同退出码 rc=3", 外层 rc=4, 无 META-OK
   - 同一编译器未注入对照 => 两项 META-OK, 外层 rc=0
   - 删 1 条必需 CASE(同时把 SUMMARY 计数改成与实际一致以隔离唯一失配点) => rc=4 缺席: SD01-...
   - 删 SUMMARY 行 => rc=4 SUMMARY 行 0 条(必须恰好 1 条)
   - 未篡改副本正对照 => rc=0 台账合同成立
   - --wrap 通道先用最小程序证明确实改变退出码, 不成立则整项记环境故障而不算检出
   修复后默认链: off_target 21 / on_target 20 全 PASS, 外层 rc=0
   修复后正常反向: R1 proc_rc=1 实际FAIL行=2 额外失败=1; R2 proc_rc=1 实际FAIL行=3 额外失败=0; 外层 rc=0
