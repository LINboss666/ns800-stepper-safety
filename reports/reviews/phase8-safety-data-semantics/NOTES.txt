4. 真实失败与修正(原样保留, 不写成一直全绿; 三条都是夹具缺陷, 未放宽任何期望)
   a) 编译期: sd06_production_context_isolation() 里第二段用了未声明的 seq
      => error: 'seq' undeclared; 补声明后通过。生产代码未改。
   b) SD05c 首跑 FAIL "失败后重新读到即恢复有效: MISS"
      根因: 夹具的 sim_inject_unresolved() 把 handle 置 -1, 恢复步骤只重设了读数,
      没恢复解析句柄 => ENN 仍解析不出来。补 sim_restore_resolved() 后 PASS。
      生产代码未改, 期望未改。
   c) SD11c 首跑 FAIL "offsetof(flags)=44 (期望 56)"
      根因: 我把**结构体字段偏移**与 ns_storage.c 的**页面内偏移**混为一谈。实测
      sizeof(ns_fault_sample_t)=48, offsetof(flags)=44; 页面偏移 56 = 12B 记录头 + 44,
      属于 ns_storage.c 的序列化布局, 本轮未改该文件也不在本链编译范围。
      修正后的判据: 结构大小 48 / flags 仍是末字段(@44) / bb_frame_t 48 不变;
      页面偏移与 CRC 不变性由"该文件零改动 + 结构未变"共同保证(交付处按 git diff 核对)。
   d) 工具使用失误(不影响判定): 第一次 REVERSE=1 复用了同一 OUT_DIR, runner 开头的
      清理把正常变体的 *_out.txt 删掉了。随后用 SD_OUT_DIR=<LOCAL-TMP>/ns800-host-chain/sd_rev
      分离重跑, 正常链与反向链各留一份原始产物; 两份证据都来自真实执行, 未挑选轮次。

6. flags 应用载荷映射(语义版本 1; 不是 LOG1 外层版本, 也不是硬件验收版本)
   7:0 fault_code(不变) | 11:8 电平 bit8=ENN 反馈, 9=LIMIT_MIN, 10=LIMIT_MAX, 11=DIAG(位置不变)
   15:12 active | 19:16 motor_state(不变) | 23:20 safety_state(不变) | 27:24 valid
   31:28 = 1
   dump 分派: 1 => 按新定义逐路标注 VALID/INVALID_NO_SAMPLE/DISABLED_BY_CONFIG;
              0 => LEGACY_UNVERSIONED, 只打印 raw_flags, 不追认 bit8 的角色与可读性;
              其他 => UNKNOWN_SCHEMA, 同样只保留 raw, 绝不默认成 V1。
   旧记录不迁移、不重写、不清空; 直接用 ns_log API 的其他测试记录不会自动变成新格式。
