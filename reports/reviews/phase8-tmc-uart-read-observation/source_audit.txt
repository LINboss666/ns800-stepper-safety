2. 缺陷 1 的字节级定位(修前 / 修后同一处)
---------------------------------------------------------------------------
修前(blob a691eb5:tmc2209.c, 原行号):
  509: stage_cap = rt_tick_from_millisecond(TMC_REPLY_TIMEOUT_MS);
  513:     rt_tick_t used = rt_tick_get() - b->start;
  514:     rt_tick_t left = (used >= b->total) ? 0 : (b->total - used);
  515:     eff_end = b->start + ((stage_cap < left) ? stage_cap : left);
=> 阶段期限从 **b->start(预算打开刻)** 起算, 而 `used`(flush + TX 已花掉的时间)只是用来
   削小 left; RX 阶段实际拿到的窗口 = min(100, total-used), 且**起点被提前到 used 之前**,
   等于把 TX/flush 的耗时二次计费。合同 "RX 阶段 <=100 ms 且不超过同一操作总预算" 里的
   "100 ms" 因此永远拿不满。

修后(工作树/fb1a72e 字节, 现行号):
  838: stage_cap = rt_tick_from_millisecond(TMC_REPLY_TIMEOUT_MS);
  864: eff_end = b->start + used + allowance;
  868: obs->rx_begin_off = (rt_uint32_t)used;
  869: obs->rx_deadline_off = (rt_uint32_t)(used + allowance);
  其中 allowance = min(stage_cap, left), left = total - used, used 在 RX 阶段入口采样一次。
  总预算耗尽改由显式前置分支返回(-RT_ETIMEOUT / TMC_XFER_BUDGET_EXHAUSTED, RX 未进入),
  不再和"阶段窗口"混在同一个表达式里。
期限比较全部改为回绕安全的无符号差值(937/965 行 `rt_tick_get() - eff_end < 0x80000000`),
CRC 之后仍复核一次期限; 过期后到达的合法完整帧保留 crc_state=OK 与 late_valid_frame=1,
但 published/value_valid 必须为 0(URO04/URO16 断言)。

纪律核对(§5.2 补充 1..8):
  1 tx_written 只表示交给 DATA 寄存器的计数 —— 导出文本写作 "tx=%d/%d/%d off=%u", 不写"已上线";
    URO09 断言"线上真实字节 == tx_written == 2"。
  2 rx_total 在每次 rt_device_read 返回后、滑动/覆盖之前累加并取样(tmc_obs_rx_bytes),
    URO17 用 48 B 长流证明 rx_total=48 != rx_buf_n(退出时 n=16), 前缀/尾部样本分列。
  3 flush 阶段只导出计数(本轮未保留 flush 字节样本), 导出文本不宣称知道那些字节内容;

  4 crc_state 三态 NOT_REACHED/FAIL/OK; hdr_seen 与 frame_complete 分列(URO14/16)。
  5 legacy 枚举名 TMC_XFER_RX_TIMEOUT_ECHO 只原样导出 reason 文本, 回声判定一律用
    echo_state/echo_match_seen; ECHO_ONLY 只在 rx_total==4 且整段等值时才出现(URO11 vs URO12)。
  6 NOT_REACHED 的 rc/reason 导出为 `-`, timing 行写 `timing=- (budget never opened)`,
    不会出现 rc=0/used=0 伪装成功(URO19 断言)。
  7 观测路径只赋值/有界拷贝; S2 保护窗口、TX 等待环、RX 轮询环、锁内一律没有新增串口输出,
    URO20 用 leaf_lines_at_txn_release==0 直接证明"归还 txn 之前没有输出行"。
  8 probe 不改 TMC health/已配置状态/缓存, 不调 apply/清故障/保护写; URO20 同时核对
    读请求计数增量、写帧增量=0、health 未变。

6. 打印原语可用性(为什么必须有 ab76a07 这一次修正)
---------------------------------------------------------------------------
首轮集中回归在 build_and_run 上编译失败(见 host_results.txt 保留的第一次失败原文), 根因是
probe 的有界输出用了 rt_vsnprintf / rt_kputs:
  rt-thread-master/include/klibc/kstdio.h:22  int rt_vsnprintf(...)   (仅内核声明)
  rt-thread-master/include/rtthread.h:783/786  rt_kputs(条件宏 + 声明) (仅内核)
  tests/host/shim/rtthread.h        有 rt_snprintf、rt_kprintf; 无 rt_vsnprintf、无 rt_kputs
  tests/host/shim_ps/rtthread.h     同上(shim_leaf/rtthread.h:14 只是 #include "../shim_ps/rtthread.h")
结论: 公共夹具 shim 是 §10.1 禁改项, 因此产品侧只允许使用**每条链都已有**的 rt_snprintf +
rt_kprintf。ab76a07 把格式化收进 TMC_PROBE_EMIT(-> rt_snprintf) 与 tmc_probe_put(->
rt_kprintf("%s", line)), 顺带保留"短行必须容得下"的自检: 需要字节数 >= 上限或 > 96 时报
`[TMRO] EXPORT_ERROR need=.. cap=..` 并计入 export_err, 不发半条记录。
