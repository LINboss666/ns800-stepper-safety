## 2. 本轮新增的 7 个用例（登记在 OVERRIDE_CASES，LIMIT-OFF/ON 两个 OVERRIDE 变体各自执行）

| id | 断言（全部用生产 API 返回值/状态 + 仿真计数，无文本搜索） |
|---|---|
| IO4c-ready_true_on_enabled_side_ideal | `safety_drv_enable_write(1)` rc=EOK 且 `safety_protection_ready()`=TRUE（理想链，请求 HIGH、反馈 LOW） |
| IO4d-ready_false_when_cut_by_hardware | 同一请求 HIGH 下把外部链切成 ESTOP_CUT ⇒ `safety_protection_ready()`=FALSE（verdict=CUT_BY_HARDWARE） |
| IO4e-ready_false_when_sample_lost | 切成 NO_WIRE ⇒ FALSE（verdict=NO_SAMPLE） |
| IO4f-ready_true_again_after_disable_request | 写回 LOW（禁能侧）⇒ 重新 TRUE |
| IO7d-latch_kept_when_disarm_reads_stuck_enabled | 预检查 OK，disarm 写 LOW 那一刻切成 STUCK_ENABLED ⇒ 仍为 FAULT_LATCHED、故障码保持 FAULT_TMC_DIAG、LOW 写与 pwm_disable 计数已增加、注入已被消耗 |
| IO7e-latch_kept_when_disarm_loses_sample | 同上切成 NO_WIRE ⇒ 锁存与故障码保持 |
| IO7f-control_clear_succeeds_without_flip | 对照组：不布防注入 ⇒ MANUAL_CLEAR 且 fault=FAULT_NONE（证明上两条不是必然失败） |

IO4c~IO4f 刻意**不 arm**（用唯一受控写入口建立请求），因为斜坡线程的运行守卫在 armed 时每拍就会
关断，会破坏"直接读保护就绪 API"的前提；被测函数本身不取 `mot_lock`，因此无需在夹具里持锁。
IO4a/IO4b（真实 arm→start 正路径）与 IO5a~IO5c、IO6b1/b2/c、IO7a/IO7c 全部原样保留、未放宽。

仿真核新增一次性注入原语（仅存在于 tests/host，不进生产、不进 Keil）：
`io_sim_flip_chain_on_disable_write(mode)` + `io_sim_flip_armed()`，
在下一次对 `PIN_NAME_DRV_ENABLE` 写 LOW 时把外部链切成指定模型并保持该模型。
