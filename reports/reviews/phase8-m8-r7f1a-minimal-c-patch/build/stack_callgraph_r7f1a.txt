[0] 为什么换根(复审 §1 的原话复述, 不是我自己的判断)
    上一份报告用 supervisor_boot 子树(2020 B)与重定向入口 main(756 B)谈 main 栈余量, 漏掉了
    两层调用者。真实关系是 main_thread_entry -> $Super$$main -> supervisor_boot, 且
    src/components.c:200-204 在 __ARMCC_VERSION 下就是调 $Super$$main(); 因此整条 main 线程
    的静态深度要以 main_thread_entry 为根。本报告同时列两版镜像的同名数, 差支可直接对账。

[2] 预算判定(RT_MAIN_THREAD_STACK_SIZE 2048 -> 4096)
    修前: main_thread_entry 2076 B / 预算 2048 B => 静态差值 +28 B(超出预算, 这就是复审 §1 的结论)
    修后: main_thread_entry 2076 B / 预算 4096 B => 静态差值 -2020 B(预算内, 余量 2020 B)
    边界照旧: Max Depth 是 armlink 静态下界(不解析函数指针, 不含异常/ISR 帧与上下文保存),
    所以"余量 2020 B"不是"证明不会溢出", 只是可核对的静态形状。

[3] 4096 这件事落在哪里(资源侧实测, 不是推断)
    rtconfig.h 有 RT_USING_HEAP(rtconfig.h:103), src/components.c:172-177 的静态数组
    main_thread_stack[] 在 #ifndef RT_USING_HEAP 里, 本目标不编它; :218-221 走
    rt_thread_create("main", ..., RT_MAIN_THREAD_STACK_SIZE, ...) => 这段栈来自堆。
    所以本轮 ZI 增量实测为 0(见 §4), 而**运行时堆占用 +2048 B**:
      堆区间固定 board.h:30-31 HEAP_BEGIN=&Image$$RW_RT_HEAD$$Limit,
      HEAP_END=同一个符号 + 0x8000 => 整个堆 32768 B, 主线程栈请求从 2048 变 4096。
    离线无法测堆峰值, 因此这条只能登记为"下一次现场的可见事实":
      若堆不够, rt_thread_create 返回 RT_NULL, components.c:221 的 RT_ASSERT 会在
      [BOOT] 横幅之前就炸掉; 反过来, 只要 [BOOT] 逐行照常出来, 就说明这次分配成了。
