# 给现场 agent：R7F5A 两路分析仪采集 + 一次静态 IRQ 试验

日期：2026-11-04。本任务已承接操作者“DIAG是IO3吧 没错的话可以给agent下发任务验证了我已经接好线了”的授权；A 已核对映射。执行端在本机 D:/ns800 操作。本包由 A 离线准备，A 没有操作现场设备。

## 目标与测点

取得同一连续采集中的 DIAG 和最终 TMC_ENN，并与原 R7F5 的静态状态响应对照。电机始终禁能，零 arm/start/运动；不人为产生 DIAG 报警。

| 操作者探头命名 | 已接信号 | 源码/既有接线映射 |
| --- | --- | --- |
| CH1 | DIAG | GPIO3 / PA.3 / J4-15，即本板 IO3 |
| CH2 | 最终 TMC_ENN | 扩展板 H6-5，反馈到 GPIO70 / PC.6 / J4-40 |
| GND | 公共信号地 | 分析仪与被测两板的同一参考地 |

同一根直接连通的 DIAG 线使用一个通道即可；不要求再分别测两端。CH2 不是 PC.23/J4-21 的 MCU_DRV_ENABLE 请求信号。按操作者已经接好线的事实推进，不再重复询问同一接线或机械装配。软件通道可能从 0 编号；记录探头印字与 GUI 实际通道号的对应，不能凭“第一路”猜映射。

## 开始前：只做必要核查

1. 核清上述文件与旧账；确认已有 Logic 界面和设备状态。当前截图仅证明 Logic 1.2.17 曾显示 Connected，不能由软件版本或 USB VID/PID 推定实物输入耐压。以本机已有硬件规格/型号资料核实支持被测逻辑电平，未核清则在上电/采集/开 COM 前回报缺项。GND 只接公共信号地，探头不接 VM 或电机相输出。
2. 记录实际 GUI 通道号、探头命名、信号名。只启用这两路数字采集，关闭通道反相和协议解码；不改变原电路接线、驱动参数或其他板端开关。
3. 优先使用数字采样率 **1 MS/s**，记录设备实际支持值。设置一次采集能覆盖串口流程，建议容量不低于 **100 M samples**（1 MS/s 时约 100 s），不要先做“试采”消耗一次机会。若 UI/设备不支持足够覆盖时长，Start 前报告；不把短于现场会话的捕获算全程证据。
4. 沿用本机已连接的 Logic 界面；能可靠操作 GUI 就用 GUI，不能可靠操作时由操作者完成同一轮 Start/Stop/保存，agent 读取产物。无需安装驱动、替换软件、直占 USB 或另造 Python 采集框架。界面截图按新鲜画面定位，点完核实状态，不把 SendInput 返回成功当作已经采集。

补正前次工具判断：官方确有 [Legacy Logic 1.x API](https://www.saleae.com/support/extensions-api/automation-api/automation-legacy-logic1)。未监听某端口，只能说明本机当时该通道未就绪，不能推出“Logic 1.x 没有 API”。本轮无需为此开启新服务或研究新控制链，使用当前可用界面即可。

## 一次执行的顺序

1. 如现场仍断电，操作者先给 VM，再给 MCU 供电一次；VM 应在 IOIN 自检前就绪。若已上电，不为本轮额外复位；原计划第一条状态检查负责确认本次实际运行态。没有另开终端、额外 COM 会话或额外查询。前置不符即停，不做故障复位来凑条件。
2. Start 分析仪一次，确认确实在采集，记录开始时间、设置和截图，再运行原计划一次。若启动采集失败，保留失败原文，串口流程不开始；不重试。
3. 用新批准身份和持久账执行原计划，真实入口必须同时包含 `--dispatch --transport real --backend real --profile response_driven`，使用原文件身份以及匹配的实际授权令牌。不要漏 `response_driven`，不要修改原执行器或拆成随手发命令。
4. 固定串口链仍为：只读前置 → 一次配置 → 检查 → 临时软件标志 → 开 IRQ → 有限静态观察与查询 → 关 IRQ → 禁能状态收口。全程零 arm/start；门变绿也不延伸动作。不要把 LA Start 当成板端动作执行第二轮的理由。
5. 串口正常结束并关闭端口后，Stop 本轮采集一次；随后操作者切断 VM 与 MCU 供电，清掉试验 RAM 标志，再保存/导出。若出现异常、LA 丢失采集、程序失联或到外部 90 s 截止，先由操作者切断两路供电，再结束采集；不等软件恢复、不为补尾再开口/重采。断电尾段和上电过渡单独标识，不能混入稳定供电时的值判定。
6. 原生捕获按软件实际格式保存；从当前这同一份捕获导出带时间戳、两路独立 0/1 列的数字原始 CSV，优先“每次变化一行”并保留初始状态。不是协议解码结果 CSV。记录实际导出选项、文件字节数和 SHA256。导出失败不重采，不补造原始数据。

## 判据与必须保留的边界

- 在明确稳定供电、覆盖串口静态流程的窗口内，DIAG 预期低，最终 ENN 预期高；与 `safety_irq_status` 的 `TMC_DIAG pin=3 raw=0 safe=0 irq=RISING` 和 `safety_status`/`system_status` 的 ENN_fb=1、禁能 verdict=OK 对照。
- 统计每路初始/结束值、上升/下降沿数、异常脉冲与采集覆盖区间；一条平线也如实报告，不画出不存在的边沿。若 CSV 未导出初始状态，不能从空边沿表补造整段电平；回到同一原生捕获读取，并明确证据来自哪里。
- 必须取得串口原计划本身的判读结果，不能因 LA 静态值正常就跳过原计划首错；反之，串口全绿而采集无效/未覆盖也不能宣称本轮仪器对照通过。
- `polarity_measured=false` 保持不变：本轮能证明正常静态逻辑值，不能证明报警态和物理极性两态；没有 DMM 就不能报告电压数值。`core_protection_verified=false` 保持不变。
- 原 `safety_polarity_confirm CONFIRM` 仍仅是已经披露的**无使能试验临时置位**，不是“LA 接上了所以极性已经实测”。结束断电清除，不把它作为运动前置证据。
- 没有共同硬件时间标记时，LA 与串口墙钟不能用于宣称微秒级 DIAG→IRQ/禁能延迟。原生采样分辨率也不等于板端实测响应延迟。
- 零 arm/start 条件下 ENN 一直高是预期。不得通过拉线/跳线强拉 DIAG、堵转、过热、短路等方式制造边沿；保护触发、恢复、正常 arm/disarm、SG/ADC/IMU 与运动仍未验证。

完整成功的名称建议 `STATIC_IRQ_TRIAL_WITH_DIAG_ENN_CAPTURE_PASS`；若只是部分有效则分别报告串口结果与仪器结果，不拼成全过。首错停止，保留已得数据，不重试。
