[6] RAM 读取窗口的依据
  map 中的数据区域(逐行取自 rt-thread-a0.map):
    Execution Region ER_IROM1 (Exec base: 0x08000000, Load base: 0x08000000, Size: 0x000415f4, Max: 0x00080000, ABSOLUTE)
    Execution Region RW_VT_DTCM (Exec base: 0x20000000, Load base: 0x080415f4, Size: 0x000003cc, Max: 0x00000400, ABSOLUTE, COMPRESSED[0x00000008])
    Execution Region RW_DTCM (Exec base: 0x20000400, Load base: 0x080415fc, Size: 0x0000ea30, Max: 0x0001fc00, ABSOLUTE, COMPRESSED[0x00000238])
    Execution Region RW_RT_HEAD (Exec base: 0x20012000, Load base: 0x08041834, Size: 0x00008000, Max: 0x00008000, ABSOLUTE)
  允许区合并: 下限 = RW_VT_DTCM 基址 0x20000000;
              上限 = RW_DTCM 基址 0x20000400 + Max 0x1FC00 = 0x20020000 (开区间)。
  该上界来自 scatter 区域 Max, 是本包**读取范围**的上限, 不是整颗芯片 RAM 规格。
  堆范围(board/board.h: HEAP_BEGIN=&Image$$RW_RT_HEAD$$Limit, HEAP_END=+0x8000):
    Image$$RW_RT_HEAD$$Limit = 0x20012000 (SHN_ABS, size=0)
    => HEAP = [0x20012000, 0x2001a000), 32768 B
    sensor 的 TCB 与 4096 B 栈都由 rt_thread_create 从该堆分配, 故必然落在上式区间内;
    距批准窗口上界 0x20020000 还有 24576 B。
  勘误(本轮自查): 进入本轮时曾把该 Limit 符号按「区域末地址」理解, 得到 HEAP_END=0x20022000,
    据此设想「TM 栈可能落在批准窗口之外」。实测 symtab 值为 0x20012000(区域基址; ZI-only 区域的
    Limit 符号等于基址), 该设想不成立; 上述算术即为更正后的口径。
  物理 RAM 与窗口的关系: 设备头给出 SRAM 256 KB(上至 0x20040000), 批准窗口比物理 RAM 窄;
    落在窗口外的对象一律在读之前拒绝(fail-closed), 不擅自放宽窗口。

[7] 预登记的拒绝分支(与 dry-run 一一对应, 见 dryrun_matrix.txt)
  AXF 字节不符 / s_tid 或 _cpu 绑定不唯一 / 类型布局跨 CU 不一致 / 入口 DWARF 与 symtab 不符
      -> bind() 直接 Refuse, 不创建会话(设备侧零动作)。
  s_tid == 0 (线程尚未创建) -> 记录原值后停止, 不扫描内存。
  TCB 未 4 字节对齐 / 越出窗口 / sizeof 超过 1024 -> 读 TCB 之前拒绝。
  name != 'sensor' / entry != low_pc|1 / stack_size != 4096 -> 记录 TCB 原值后停止, 不读栈。
  栈 base+4096 越出窗口, 或长度不是 4096 -> 读栈之前拒绝(不因动态值重新请示, 但也不放宽)。
  累计读数超过 16384 B -> 下一次读取前拒绝。
  系统寄存器只有在地址等于推导值时才允许读; 否则 SYSREG_NOT_BOUND。
