6. 失败根因(附录采集器的变量名碰撞, 有独立最小复现)
==============================================================================
  抛错链: 台账先写 RX_FILE(003_spm_status, 139 B, 第一支只读查询正常完成), 紧接着
    STOP_FAILURE "Previous reply still open."; stderr 另有一条 PowerShell 方法错误。
  PowerShell 变量名**大小写不敏感**: 顶层脚本作用域里 $reply 与内部状态 $script:Reply 是同一个变量。
  附录自检分支在脚本作用域写了三处赋值:
      A0BoardBSerialR1.ps1:236  $reply=Cmd 'spm status' 1000; Idle-Status $reply
      A0BoardBSerialR1.ps1:240  try {$reply=Cmd 'spm status' 250} catch {
      A0BoardBSerialR1.ps1:246  $reply=Cmd 'spm status' 1000; $badStatusSeen=$false
    => 第一支 $reply=Cmd … 把返回的 PSCustomObject 写进了 $script:Reply, 内部状态被自身返回值覆盖;
       第二支 Cmd 的 Begin-Reply 见 $script:Reply 非空即抛 "Previous reply still open.";
       finally 里对 PSCustomObject 调 .Dispose() 又报"不包含名为 Dispose 的方法"。
  独立最小复现(本机我自己写的机制样本, 不是附录文件, 也未修改附录):
    WORK_OUT_R1/r1_reply_var_repro.ps1  1401 B sha256=4d745fefa9f576fcada10eef3fe3b2b5afde06d562e793a98da458ed9259ff89  rc=0 stderr=0 B
      STEP1_first_open_close=OK
      STEP2_state_variable_type_after_assign=PSCustomObject
      STEP3_same_object_as_return_value=True
      STEP4_second_open_threw=Previous reply still open.
      STEP5_dispose_threw=方法调用失败，因为 [System.Management.Automation.PSCustomObject] 不包含名为“Dispose”的方法。
      STEP6_script_scope_reply_variable_exists_and_is_the_returned_object=True
    STEP2/STEP3/STEP6 说明同一个变量被返回值顶替, STEP4/STEP5 与真实失败的两条错误逐字同形。
  影响面(只到证据支持的 extent):
    - 联机分支不含 $…=Cmd 到 reply 的赋值(上表三处都在自检分支), 且 [IO.Ports.SerialPort] 只出现在
      联机分支与 finally 释放处; 因此该碰撞**阻断的是离线自检**, 不据此断言联机路径也有此错。
