## 4. 源码约束：定稿时必须保留

### 4.1 学习与配置身份

- 驱动配置状态参与 profile 签名。因此先确定并应用最终驱动配置，再在可信静止、禁能状态重新取零点；不能直接沿用 R7F7 在 UNCONFIGURED 下取得的零点。
- 学习在 MONITOR_ONLY 下进行。正常样本必须处于指定方向、速度窗和 CRUISE 阶段，采样身份一致；ADC 与 SG 要各自取得独立新样本。数值不变不代表没有新样本。
- `STARTED` 只代表受理；以 `learn_status` 的终态、计数、归属和凭据验收。后台软件 deadline 仍为 12 s，不修改线程栈或时限换取通过。
- 新 learn 受理会作废旧 learn 凭据。因此本轮顺序为**先活动取消，再最终成功学习**；最终 DONE 后不再为测试取消而受理新 learn。
- `learn_cancel JOB_ID` 不负责停止电机。已经 DONE 后返回 NOT-CANCELLED，不能算活动取消成功；未命中取消窗口也不能擅自重开作业。
- commit 与诊断模式切换均要求静止事务。成功学习后先 stop/disarm，再 commit、开启相对保护；不能到巡航后才临时切模式。
- commit 成功保持 zero／learn 凭据，不自动设为 FIELD_VERIFIED，不自动写 Flash。

### 4.2 保护引擎

| 目标 | 实际判据要点 | 不可替代的证据 |
| --- | --- | --- |
| SG | 相对学习所得 `run_sg_min` 的下降量；达到 trip、持续时间与独立新 SG 数量要求 | 当前事件首因 `REL_SG_SEVERE`；硬件 DIAG 先停不能冒充此项 |
| ADC | 当前 ADC 到学习正常带之外的距离；正常带由 min／max 与噪声展开；达到 trip、持续时间及新 ADC 数量要求 | 当前事件首因 `REL_ADC_SEVERE`；不预设负载一定使原始 ADC 向上变化 |
| IMU | 独立冲击门：新鲜 `vib_mg` 峰值，在规定时间窗内达到独立新样本数要求 | 当前事件首因 `REL_IMPACT`；不是 SG／ADC 式相对学习阈值，也不是把约 1 g 重力当碰撞 |
| 双源融合（按最终声称纳入） | SG warn 与 ADC warn 重叠，并满足持续与各自新样本要求 | 当前事件首因 `REL_FUSED_SEVERE`；单源 severe 不算融合通过 |
| 源失效／覆盖异常（另定范围） | 年龄、运动事实、工况窗口或覆盖不可用引发的独立降险路径 | 分别判 `REL_SENSOR_UNAVAILABLE`／`REL_OUT_OF_WINDOW`／`REL_COVERAGE_LOST`，不算目标负载通道通过 |

IMU 不可用不会自动否定 SG／ADC，但 IMU 本项必须保留未验证。正常加减速阶段有窗口例外，抑制 SG／负载判据；源失效检查仍有效。必须核对实际阶段与新鲜度，不能把这一例外写成“任何加减速都受同等负载保护”。

同一帧内先检查冲击，再检查 SG severe、ADC severe 和融合；另有更早的覆盖／源异常检查。不同通道一起越线时，按真实首因判，不靠试验名称归因。

### 4.3 停机与恢复

- `motor_stop` 受控减速到零后可能仍 armed、驱动请求仍 HIGH；它不等于 disarm。
- `motor_disarm` 后核对 armed=0、cur/tgt=0、请求 LOW、输出 pad=0、最终 ENN 高且反馈一致，并核对停脉冲返回结果。
- 软件事件投递成功、PWM API 接受关断，不等于已经用仪器证明最后一枚 STEP 的物理时刻。
- 相对保护触发后进入 MONITOR_ONLY 并要求人工重新建立保护代次；故障源恢复正常不会自动恢复保护或运动。
- 恢复计数需要独立新样本与两个源的正常证据。计数满足也不等于 Safety 故障锁存已清除；`fault_reset` 仍有自己的源安全、禁能与停脉冲复核门。

## 5. 建议现场顺序

本表是待定稿流程，不是可直接 dispatch 的命令表。<参数> 都必须在正式包中替换为确定值，查询次数和退出条件同时落定。可在一个正常巡航段内完成取消与成功学习，不为目录拆分额外增加运行。

### P0 — 承接与只读基线

核对在板镜像证据的承接与操作连续性，再只读检查 READY/fault、驱动配置、诊断模式、作业状态、arm 门、IRQ／极性、传感器有效性与静止禁能反馈。作业预期起点允许 §1.1 的旧 FAILED 记录，不误判为本场新失败。现场与交接不符则停止，不靠复位／clear 清场。

**通过条件：**身份链连续；操作员和机械条件满足定稿；当前状态与正式计划一致；所有运动门禁闭合。不开运动去试门禁是否碰巧能过。

### P1 — 最终驱动配置与新零点

必要时按明确配置执行一次 `tmc_config_apply CONFIRM`；确认实际 CONFIGURED 及 IFCNT 验证，再在 MONITOR_ONLY、可信静止禁能下执行 `diag_profile zero <N_ZERO>`。

**通过条件：**配置与批准值一致；零点成功、owner=FREE、zero 凭据有效；候选签名绑定最终驱动身份。零点失败后不追加尝试。

### P2 — 一段正常运行：活动取消 → 正常 DONE → 正常停止／禁能

1. 静止设置 `motor_dir <DIR>`、`motor_target <HZ>`；按正式计划 arm/start，确认真实巡航及学习窗成立。
2. `diag_profile learn <N_CANCEL> <LO> <HI> <DIR>`。从真实 STARTED 回包提取 JOB_ID，按固定时序对这一枚活动作业执行 `diag_profile learn_cancel <JOB_ID>`，有界查询 `learn_status`。
3. 验收 REQUESTED 与最终 CANCELLED、owner=FREE、无遗留 cleanup；确认取消未被当作电机停止。若已 DONE、FAILED 或未捕获活动取消，分别登记，不记成 CANCELLED，不临时再开一枚。
4. 在仍满足同一正常工况且总运行时限有余量时，创建最终成功学习：`diag_profile learn <N_DONE> <LO> <HI> <DIR>`。
5. 在任务进行中取得状态查询响应，记录受理耗时、查询耗时、进度和终态。必须达到 DONE，ADC／SG 各自达到请求样本数，owner=FREE、凭据 zero=1／learn=1，候选统计与阈值可用。
6. `motor_stop`，有界等待可信零速；记录 stop 后 armed／驱动状态。再 `motor_disarm`，验可信禁能与停脉冲结果。

**通过条件：**活动取消与正常 DONE 两项各有自己的 JOB_ID 和证据；命令没有等满后台采集才返回；学习不改变已批准电机工况；正常 stop 与 disarm 分开证明。作业失败或取消不释放运行截止义务；收口仍须执行。

若学习数据无法生成可分辨阈值，记录原始失败和统计，停止；不临时换 tier／阈值或额外学习。活动取消可观测窗口与查询预算必须在定稿中解决，不能现场临时改 deadline。

### P3 — 静止提交与保护使能

可信静止、禁能后执行 `diag_profile commit`，只发布 RAM 候选；保存 profile 的 id／rev／签名、工况、全部阈值和时间／年龄参数。再执行 `diag_mode relative CONFIRM_EXPERIMENTAL`，确认本场新保护代次和有效覆盖。

**通过条件：**提交的就是 P2 最终 DONE 候选；两份共享状态一致；FIELD_UNVERIFIED 如实保留；模式切换与代次可查。不得把旧日志或旧 profile 当本次发布。

### P4 — 分通道目标刺激

分别安排 SG、ADC、IMU 场景。每场均按“新代次／arm/start → 正常巡航无刺激段 → 单项受控刺激 → 目标首因 → 停机禁能 → 恢复”执行。

- 无刺激段记录有效源、工况与正常值，作为本场负控；正常段误触发则先停，不再继续施加刺激。
- 每场只采用已定稿的刺激方法、上限、时间与次数。超过窗口仍未命中，立即正常停止／禁能并记 NO_TRIGGER；不加大刺激碰运气。
- 若先出现其他通道、硬件 DIAG、源失效或越窗，保存真实首因并收口，目标项记“未证／被其他原因抢先”，不拼为通过。
- 三场可以共用已绑定、未漂移的 profile；配置、方向或工况身份改变时先停止并重定方案，不自动重新学习。
- 若最终需要声称双源融合保护，另加 FUSED 场景及额度；没有这场就保留 NOT_VERIFIED。

**通过条件：**目标判据的输入依据、新鲜度、首因与停机链均可归于本次事件；响应／物理延迟只报告实际可测的范围。

### P5 — 每次故障后的恢复与最后正常收口

1. 保存本次首因与关断结果，确认无继续运动。解除刺激，观察源恢复；不在活动故障源上反复运行 reset。
2. 在满足源码恢复门和人工条件后，按正式额度执行 `fault_reset`；核对回到允许状态、无自动起转，旧事故记录仍可追溯。
3. 如需继续下一场，显式建立新的相对保护代次、再 arm/start；不能沿用已消耗的旧代次。下一场启动也承担自己的时限与收口额度。
4. 最后一场恢复后安排一次限定的正常保护运行，验证没有自动启动、人工重启有效、无刺激无误报，再正常 stop/disarm。
5. 留下可信禁能最终快照，记录模式／IRQ／profile 的最终状态，正常保持 VM 与 MCU 供电。只有实际需要独立断能时，记录真实原因和操作事实。

**通过条件：**每次预期故障均有可追溯的解除与人工恢复；没有自动重启；最终正常 stop/disarm 成立。恢复被拒也按真实结果登记，禁止循环 reset 直到变绿。

## 6. 仪器证据与判读边界

- 现有 DIAG＋ENN 两路可以记录两条线上实际发生的变化。arm/disarm 产生的已知 ENN 状态转换可增加探头通路的区分力；不能顺带证明 DIAG 接触或极性。
- 仅靠这两路不能证明实际 STEP 脉冲已消失，也不能量化最后脉冲到停机的时延。若正式验收需要这项，另列 STEP 测点／第三通道或其他独立测量方法及批准范围；否则保留物理 STEP 结论未验证。
- 不把“Channel 0 低、Channel 1 高”当成映射证明。软件列名、操作者接线说明与观测事件分别保存；DIAG 一直不变时，仍不能宣布 DIAG 极性已测。
- 每场采集窗须覆盖实际事件与收口；按采样率、通道数和最长期限核保留长度。接口仅返回请求缓冲值时，写“请求”，不写“已证明可容纳”。
- 串口主机时间、分析仪时间与物理动作时间注明各自来源及误差。仅有包住会话的时间窗，不等于已经建立亚毫秒事件对齐。
- 使用现有输出和快照取证；不足以证明逐样本计数、先后或精确延迟时，标证据不足。不要为了写全结论而假造连续曲线。
- 原始串口响应、台账、CSV 和原生捕获保留字节身份；公开副本的设备标识处理明确登记。历史原件不回改。

| IMU 目标首因 | NOT_RUN | 本次 REL_IMPACT、新鲜峰值与计数依据、停机／禁能、恢复 |

正式包生成前：
1. 将所有 TBD 换成确定值，绑定 R7F7 回执与实物条件，列出完整命令、动作总次数、时限和退出分支。
2. 核对执行器是否支持新学习命令、精确的预期作业／保护故障及收口。若现有执行器不能表达，先离线完成必要适配和反例，不现场去掉错误门。
3. 对真实源码／source_shape 推导响应和最长打印；预期故障白名单只对当前阶段、原因和代次生效，不放过关断失败、字节损坏或无关故障。
4. 先离线验证计划、额度和首错／截止／恢复分支，再定稿并取得一次覆盖明确范围的批准；不把本草案视为批准令牌。
