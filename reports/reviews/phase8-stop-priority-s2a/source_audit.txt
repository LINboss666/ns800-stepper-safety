  (再关 STEP + 再拉 LOW + 投 EVT_DRV_FEEDBACK)。方向保守, **但**在 B 已锁存 FAULT_LATCHED 之后再发生
  一次"回滚 + 投事件", 事件链会再次 force_shutdown(自激风险取决于幂等与合并, 见 design §5.6)。
  若 :874 的确认在 B 拉 LOW **之前**就返回 OK(反馈线响应慢/采样恰好读到旧值), A 继续到 :900 提交 armed=1
  => **停机之后**许可仍被拉回 HIGH(arm 在 :821 之后再没有看过 Safety 状态)。=> S2-P04/P05 要打的洞。

R-2 停机 vs 诊断 enable(step_pwm 无锁窗口)
  A = tshell(20) 过 step_pwm.c:176 grant(Motor 侧 armed=0/静止/焊盘 LOW 都成立), 停在 :202/:208 之前。
  B = safety(4) force_shutdown -> step_pwm.c:261->:65 step_enabled 仍为 FALSE => 走 :69-86 "未持有输出",
      返回 EOK, **不**关通道、**不**置锁存。
  恢复 A: :208 rt_pwm_enable -> :214 step_enabled=TRUE => STEP 在 Safety=FAULT_LATCHED 之后开始输出,
      且 Motor/诊断两侧都没有任何"这次开过输出"的记录(mot.stop_result 仍停在上一关断结果)。
  注: 目标构建里这条路径被 STEP_DIAG_ISOLATED_ENV/MOTOR_HARDWARE 两个宏挡在 grant(:1203), 因此
      **今天不可达**; 但它是宏翻转为 TRUE 后第一时间生效的结构缺陷, 必须在 S2 方案里解决, 不能靠宏。

R-3 停机 vs 斜坡线程取到旧目标
  A = motor(8) 在 motor.c:483 取 mot_lock, :484 读 target_hz, :511 步进到非零, :535 mot_pwm_apply
      -> rt_pwm_set(:261) + rt_pwm_enable(:263)(仍在 mot_lock 内), 提交 stop_result=OUTPUT_REQUESTED。
  B = safety(4) 想在 A 之前关断: motor.c:1144 mot_lock —— 只能等 A。
  结论: 这段靠 mot_lock 序列化, STEP 不会在关断后**被斜坡重新打开**(A 的 enable 一定早于 B 的 disable
      或晚于 B 的整个动作但被 armed=0/state=FAULT 挡住下一次拍)。
      但反过来: 若 rt_pwm_set/enable 在设备层卡住(未测, TBD), **B 的首次关断动作被 mot_lock 挡住**,
      许可 LOW 也在 :1155 之后 => 一条"只为设频率"的调用可以推迟真正的关断。
      这是"首次保护动作与慢处理必须分开"的直接证据(而不是猜测)。

R-4 "投了事件"不等于"已停"
  A = motor(8) 守卫判停后在 motor.c:401 (void)safety_post_event(...); 自己已经在 :388/:394 做了两个硬件动作。
  B = 若 ss_lock 被 tshell 的 fault_reset 持有(:383-528, 内含多个 mdelay 与 ~10 次 rt_kprintf),
      safety 线程消费到事件后只能在 :165 等待; 期间 Motor 已停, 但 Safety 状态仍是旧的(READY),
      fault_reset 正在往 MANUAL_CLEAR 走。
  恢复 B: force_shutdown 拿到锁后**无条件**重做停机动作并把状态写成 FAULT_LATCHED(:218),
      把 fault_reset 刚清的锁存与 MANUAL_CLEAR 之后的语义搅在一起(顺序取决于 A/B 谁先写)。
      注意 fault_reset 在 :526-527 清锁存是在它自己的临界区内 —— **较新的失败锁存可能被这一次恢复抹掉**。
  => 需要"代次/epoch"而不是"再查一次": design §5.5、用例 S2-P09。

R-5 fault_reset(慢) vs 新故障
  同 R-4 的锁关系; 补充一条: fault_reset 自己 :451 调 motor_disarm, disarm 失败时 motor.c:940 会**再投一次**
  EVT_SOFT_FAULT。tshell(20) 持锁期间被 boost 到 4, 与 safety(4) 同优先级 => safety 阻塞到 fault_reset
  全部复核与打印做完。可下的结论: 停机请求的"首次保护动作"可以被一次人工恢复的有界采样+日志推迟;
  不可下的结论: 推迟多少 ms(未测)。

R-6 影子字段竞争(数据正确性, 不阻塞)
  mot.drv_en_request 由 mot_drv_en_request 在**锁外**写(motor.c:141); safety_drv_enable_write 也被
  pin_status(safety_gpio.c:336)/selftest(safety_state.c:279) 从 tshell 直接调用, 它们只更新
  sg_drv_en_request(safety_gpio.c:172) 不更新 mot 影子 => mot_fb_request_basis(motor.c:574-581) 与
  safety_protection_ready(safety_thread.c:311-319) 可能基于**不同的**"最近请求"判定。
  另: mot.stop_fail_latched 被 motor.c:1263(motor_pwm_grant_to_diag)**无锁直接读**。

R-7 系统级: 关中断窗口 vs 事件/ISR
  blackbox_trigger(blackbox.c:414) 与 rt_event_send(src/ipc.c, DV 函数体)都用 spin_lock_irqsave;
  Cortex-M7 上 rt_hw_interrupt_disable = CPSID I(全掩码) => 若在关中断窗口里做 STEP off + 许可写,
  期间的 GPIO EXTI/DIAG 与 UART RX 中断会被推迟(设计必须量化窗口内指令数, 见 design §5.4)。

8. 与 S1 合同的一致性检查(DV, 只读)
--------------------------------------------------------------------------------
保持不变的机制(本轮未动代码, 仅确认其调用形状):
 - 两个原始 rc 分列: motor.c:231-235 mot_stop_merge + :1157/:928 日志分别报告 PWM 与许可结果。
 - 失败锁存只由人工恢复清除: motor.c:635-640 / step_pwm.c:254-257 的唯一调用点在 safety_state.c:526-527。
 - 诊断失败不释放所有权: step_pwm.c:101-118(仅 EOK 才 step_enabled=FALSE)。
 - 统一停机不投事件: safety_state.c:150-225 无 safety_post_event; step_pwm.c:259-262(force_stop)不投。
 - 第 7 门只追加: motor.h:95 MOT_GATE_STOP_UNCONFIRMED = 1u<<6(motor.c:603 消费)。
 API 能力的真实边界(新事实, DV): HAL/drv_epwm.c:588-593 的 disable = 一次 MODIFY_REG(TBCTL.CTRMODE=
 STOP_FREEZE)后**无条件 return RT_EOK**; STD/StdDriver/Inc/epwm.h:2521-2524(AC!)显示该 helper 返回 void。
 另外框架层 rt_pwm_disable(channel<=0) 会先对 HAL 发一个 **PWMN_CMD_ENABLE**(rt_drv_pwm.c:189-191),
 ns800 的 switch 不认该命令 => default 返回 -RT_EINVAL(drv_epwm.c:625-627), 但该值被 :196 的
 result 覆盖后再不上抛。可下的结论: (i) 该驱动**不会**因关断失败返回非 EOK(除非设备指针为 NULL),
 (ii) enable/disable 是**整个 EPWM 模块**的时间基模式, 不是 per-channel, (iii) S1 的"api-failed 锁存"在
 当前驱动能力下几乎不可达 => 设计必须把"关断的可信度"落到"寄存器写已发生 + 反馈/波形另行证明",
 不能把 EOK 读成"通道已停"。不可下的结论: STOP_FREEZE 后 PA0 的实际电平/波形(TBD, 无示波器, 未上板)。
