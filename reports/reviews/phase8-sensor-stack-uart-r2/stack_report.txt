  sensor 线程自己那条链的静态已知最深值 = 1228 B(A0) / 1228 B(default), 两者相同。
  旧配置 1024 B < 1228 B => 上一轮 20.017 s 内 243 次告警与此一致; 新配置 4096 B 留 2868 B 余量。

== 3. 这份报告没有给出的东西(不编造) ==
  1) 完整最坏栈界: armlink 自己把镜像级度量写成 'Maximum Stack Usage = 2996 bytes + Unknown(Cycles, Untraceable Function Pointers)',
     即存在 Cycles(互递归)与不可追踪函数指针(msh 命令分发、线程 entry、device ops 等),
     静态调用图**不给闭合上界**。
  2) 异常/中断进入线程栈的硬件压栈不计入静态度量(M7 异常帧视 FP 上下文而异) => 记未知。
  3) 真实高水位需要上板实测(如栈填充模式 + 边界回读), 本轮零设备动作, 未测, 不声称。
  4) 未为本次通信诊断另造 WCET 平台(任务书 §3 明确不要求)。

== 4. 因此本轮对 4096 的表述边界 ==
  可以说: 4096 大于静态已知最深链 1228 B, 且旧配置 1024 连静态已知值都装不下; 报告没有显示 4096 不足,
          所以未动用'据证上调到 <=8192'的许可。
  不可以说: 4096 是已证明的最坏栈界; 板上告警已消失; sensor 路径已做过栈溢出实测。
  主机侧改一个常量的断言不等于目标栈验证 —— 本轮没有写这种假证明。
