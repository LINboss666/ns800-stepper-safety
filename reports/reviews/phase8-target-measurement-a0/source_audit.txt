================================================================ A. 三个被测入口的现有形状（本轮不改语义）
A-1 `sp_win()/sp_end()` —— APP/stop_priority.c:97-102 / :105-110。
    sp_end 的固定顺序是 `SP_BARRIER(); if (sp_win_nest > 0) sp_win_nest--; rt_hw_interrupt_enable(l);`
    屏障宏在目标分支展开成 `__DSB()`（:37），主机分支展开成 `__atomic_thread_fence(SEQ_CST)`（:39）。
    `sp_intr_masked()`（:170-186）在目标上直接读真实 PRIMASK（:44 自带 `mrs` 原语），
    与嵌套计数取并集 —— 这是"命令必须只在普通未屏蔽线程上下文执行"这条门禁的既有同源事实。
A-2 `sp_trip_fast()` —— APP/stop_priority.c:503-513（窗口 + 一次 sp_protect_held + SPM_END + 原返回）。
A-3 `sp_trip_for_operation()` —— APP/stop_priority.c:521-556（陈旧身份早退出口 + 真保护出口）。
A-4 `sp_off_attempt_for()` —— APP/stop_priority.c:642-745，七个出口：非法 owner、陈旧身份、
    release 的 pe/le/OK 三支、保留预约的 pe 支与成功支。成功支**只**调 disable，
    不强加一次许可 LOW（:731-740），故该出口的"本次动作"必须是 pwm=1/low=0。
A-5 `sp_protect_held()` —— APP/stop_priority.c:384-409：换 epoch -> 记 first_fault ->
    `rt_pwm_disable`（句柄缺失时 -RT_ENOSYS）-> `safety_drv_permit_low_raw_held()`（与 pe 无关）->
    owner/phase/trips/proof -> 返回 `pe!=EOK?pe:le`。这两条动作彼此独立，且都在同一窗口内。

================================================================ B. 记录器插入的位置与"只在原序列之间插读"
B-1 测量开关：APP/sp_measure_a0.h:24-28（`NS800_TARGET_MEASUREMENT_A0` 默认 0）；

    `SPM_WIN` 就是 `sp_win()`、`SPM_END(l,...)` 就是 `sp_end(l)`，一个 spm 符号都不引用。
B-2 measured-enter/exit 只在 APP/stop_priority.c:119-168 的 `#if` 块内存在（`spm_pin_state` :120、
    `spm_win_rt` :145、`spm_end_rt` :158）。`spm_end_rt` 的顺序是：
    钉本次身份/两路 raw（仍在屏蔽内）-> `SP_BARRIER()` -> `sp_win_nest--` -> `spm_body_end()`
    （body_end 计数 + COUNTFLAG 终点读）-> `rt_hw_interrupt_enable(l)` -> `spm_publish()`
    （post 读 + 有效性判定 + RESERVED->COMPLETE）。

    仅在本变体编译，默认目标里连符号都不存在，见 §F 的 nm 核对）；
    预约 :122-206；窗口内起点判据 :208-265；body_end/终点判据 :267-298；
    有效性判定 :300-328；发布 :330-364；只读访问 :366；能力检查 :403-467；
    dump :469-527；clear :529-577；trip :579-590；命令族 :625-690。
B-4 预约/发布用的是**原始 PRIMASK 短段**（`SPM_RAW_WIN/SPM_RAW_END`，:112-113），

================================================================ C. 主体区间判据（COUNTFLAG）的可成立性与读取者审计
C-1 位定义（当前工程实际编入的 CMSIS）：CMSIS/core_cm7.h:1009-1010
    `SysTick_CTRL_COUNTFLAG_Pos = 16`；`SysTick_Config` 写 CTRL 于 :2307-2312 同段（CLKSOURCE=处理器时钟）；
    CMSIS/core_cm7.h:1180-1181 `DWT_CTRL_NOCYCCNT_Pos = 25`；:1222-1223 `DWT_CTRL_CYCCNTENA_Pos = 0`；
    :1713-1714 `CoreDebug_DEMCR_TRCENA_Pos = 24`。SysTick 的 LOAD 是 24 位重装值
    （`SysTick_LOAD_RELOAD_Msk = 0xFFFFFF`，CMSIS/core_cm7.h:980-981 段），
    因此"窗口内无重装"给出的区间上界是 `LOAD+1`，远小于 32 位计数器的模。
C-2 **运行期读 SysTick->CTRL 的读取者审计**：全树（LIB、BSP/applications、KERNEL/src、KERNEL/libcpu/arm，
    排除 packages/）里对 `SysTick->CTRL` 的引用只有两处来源 ——
    `drv_common.c:45` 的 `SysTick_Config(...)`（**写**，只在板级初始化一次）与本文件新增的
    `spm_port_systick_ctrl()`（APP/sp_measure_a0.c:71，测量变体独有）。
    时钟节拍入口 `SysTick_Handler`（LIB/HAL_Drivers/drv_common.c:58-66）只做
    `rt_interrupt_enter / rt_tick_increase / g_tick_test=rt_tick_get() / rt_interrupt_leave`，
    不读 CTRL；既有的 µs 延时 `rt_hw_us_delay`（同文件 :89-113）只读 `SysTick->LOAD` 与 `SysTick->VAL`，
    **不读 CTRL**，因而不清 COUNTFLAG。=> "读 CTRL 会破坏现工程其它依赖"这一条在当前编译清单内不成立，
    判据可以采用；调试器/另一核/NMI 等**本构建之外**的读取者保持显式未覆盖（M-1 边界）。
C-3 前提不成立时的行为：`spm_init_counter()` 只在 `ENABLE && CLKSOURCE==处理器时钟 && LOAD!=0`
    三条同时成立时置 `guard_ready`（APP/sp_measure_a0.c:444-452）；否则主体样本一律
    `body_valid=0 + SPM_IV_GUARD_UNAVAILABLE`，并打印 `NOT_ESTABLISHED`，不换成"未证明的差分"凑数。
C-4 嵌套：内层起点读会清掉外层的"无重装"依据 —— `spm_guard_depth/spm_guard_owner`
    （:96-97、:236-251）把**外层**也标成 `SPM_IV_NESTED_GUARD`。目标上只有不可屏蔽源能造成这种
    交错，记录器的同步合同本来不覆盖它们；这里保证的是"被扰动必标无效"，不静默报有效。
C-5 包围区间（post-pre）：本批没有独立时间基、也没有完整防混叠依据，`spm_eval()` 一律
    `enclosing_valid=0 + SPM_IV_ENCLOSING_UNPROVEN`（:318-322），**不**用主体有效性给它背书；
    pre/body_begin/body_end/post 四个原始值始终原样保留。
C-6 32 位回绕：`body_end < body_begin` 直接判 `SPM_IV_COUNTER_WRAPPED`（:312-315），
    不解释成"一次回绕内的短区间"。

================================================================ D. 计数资源与"不预设目标可用"
D-1 启用序列只置 `TRCENA`/`CYCCNTENA` 两位、保留其它位、**不清零 CYCCNT**
    （APP/sp_measure_a0.c:63-70 目标后端；主机后端由夹具模型实现同一语义）。
D-2 `DWT_CTRL.NOCYCCNT` 只能运行期读 => 未检查前 `counter_status=COUNTER_UNCHECKED`，
    且此阶段**不访问任何 PPB 地址**：`spm_ctr_read()`（:118-121）在状态非 OK 时直接返回 0 且不碰端口。
    读不到递增 => `COUNTER_UNAVAILABLE`；两种状态在记录与 `cap/status` 输出里名字不同，
    零值一律伴随 `SPM_IV_COUNTER_NOT_OK`，从不被写成"0 耗时"。
D-3 递增确认是**有限次、固定指令间隔**的两次读（:424-431 的 `volatile` 计数循环），
    不轮询到成功、不调用 `rt_hw_us_delay`。
D-4 `clock_basis` 初值 `SOURCE_ASSUMED`，只有能力检查成功才升到 `CONFIG_READBACK`
    （:434-438）；命令族**没有**把它改成 `EXTERNAL_VERIFIED` 的入口（:625-690 全文无该赋值），
    因此本批不输出"已校准 µs"。晶振/HXTL 档的未决来源沿用计划 §2.1 F-02/F-03（本轮不改时钟配置）。
D-5 stop 时**不**清共享的 DWT/DEMCR 位（`spm_stop_accepting()` :461-468 明确只做状态迁移）。
