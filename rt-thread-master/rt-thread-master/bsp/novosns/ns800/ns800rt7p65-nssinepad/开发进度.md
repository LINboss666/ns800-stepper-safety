## 变更历史

### 2026-10-18 · Phase 8-F2d：TMC2209 诊断写入口收口（待独立复审）
按 F2c 独立代码复审报告逐条修复。纯离线改动：**未烧录、未向真实 TMC2209 发出任何一次写、
电机未连接、无 STEP 输出**；`MOTOR_HARDWARE_ENABLE_PATH_VALIDATED` /
`TMC_DRIVE_CONFIG_HW_VALIDATED` / `STEP_DIAG_ISOLATED_ENV_CONFIRMED` 三道宏继续 FALSE。
基线 `04af10b`（F2c）。

- **[F2c-NEW-01 已关闭] `tmc_uart_probe` 不再写任何寄存器**：旧实现 READ GCONF → 把预读到的
  原值 WRITE 回去 → READ IFCNT 验 +1。那条写既不持配置事务锁(txn)也不过写入门禁，与并发
  apply 交错时能把 `pdn_disable` 等安全相关位静默回退，而软件快照仍停在 CONFIGURED。
  现在整段读集在同一个 txn 内完成（非阻塞 try-take，取不到就**一条都不读**，返回
  -RT_EBUSY / -RT_ENOSYS），全程 0 个 WRITE 帧；身份判据改为 IOIN 的 `VERSION=0x21`。
- **写入口结构性收口**：删除无到达确认的裸写包装 `tmc_write_reg()`（唯一调用点就是旧 probe）；
  `tmc2209_write_register_confirmed()` 改为文件内**静态**（实现与 IFCNT 确认语义一字未改），
  唯一调用方 `tmc_cfg_hw_write()` 位于配置事务内部。头文件里不再出现"能直接写真实寄存器"
  的接口，并附调用方审计表（调用方 + 用途 + 前置条件）。
- **如实声明的代价**：只读 probe 再也证明不了"写帧能到达"。2026-09-12 的 IFCNT+1 属**旧版
  真机记录**，README 对应行已明确标为历史，不冒充当前能力。
- **[F2c-NEW-02 已修] GSTAT bit2 改名 `uv_cp`**：按官方 Rev.1.09 第 25 页寄存器表逐位核对
  （bit0 `reset` / bit1 `drv_err` / bit2 `uv_cp`＝电荷泵欠压；StallGuard2 的结果在
  SG_RESULT(0x41)，GSTAT 里没有 sg2）。抽出纯函数 `tmc_gstat_decode()`（含"高位非 0 =
  不是已知形状"的 `unknown`），`tmc_uart_probe` / `tmc_status` 都走它。证据等级
  **DATASHEET-CONFIRMED（人工对照手册），不是本板实测**。bit1 原名本就是 drv_err，未误标。
- **主机夹具升级（F2c 的 A/H/C 系列判据一字未改）**：`rt_device_write` 按帧类型分开计数
  （READ 请求 4 字节 bit7=0 / WRITE 帧 8 字节 bit7=1，并记录每个寄存器的写帧数），另加可选
  **设备级假芯片**（`shim_chip_enabled`；默认关 = 与 F2c 夹具行为逐字节一致；IFCNT 只对 WRITE
  自增、读不改变它）。新增 V1 FD1..FD6 + V2 FD7/FD8 共 14 条断言：仪器自检（看得见 1 个
  WRITE 帧）、死链路 probe 只发 1 个读请求即 fail-closed、活链路 3 读 0 写且芯片 GCONF/IFCNT
  分毫未动、txn 被另一线程持有时 probe 零总线动作、锁不可用时同样零总线动作、GSTAT 9 条真值表
  且零流量、apply→probe→复核证明快照与芯片不分离，以及用旧值写回**复现**分离并证明复核抓得到
  （integrity=-RT_EIO + 第 5 门闭合 + 重新下发恢复）。
- **反向验证（证明测试不是摆设）**：篡改 GSTAT 期望表 → FD6 FAIL 且退出码 1；在固件副本里把
  旧的"写回原值"插回 probe → FD2/FD3/FD7b 同时 FAIL（芯片 IFCNT 0→1 被看见），而 FD4/FD5
  两条拒绝路径仍 PASS（它们本就该零流量）。原始输出随审核包 `evidence/` 交付。
- **验证与边界**：Keil `-r project.uvprojx` Rebuild All → **0 Error / 0 Warning**，
  `Code=144082 RO-data=60130 RW-data=2204 ZI-data=83400`；主机 V1 `PASS=25 FAIL=0`、
  V2 `PASS=22 FAIL=0`。⚠ 本轮没有烧录，所以"probe 在真机上确实只发读"仍属
  **HARDWARE-PENDING**，只有夹具的帧计数证据。F2c-RISK-03（守卫时延无上界）与 F2c-RISK-04
  （U5 与门/急停非门/TMC_ENN/H2/IO70 硬件链）本轮**未触碰**，仍是运动验收的阻塞项。
